# LSTM 후보 재학습 및 비교 결과

## 실제 수행한 작업

- 원시 EAR 대신 `(좌EAR/좌기준 + 우EAR/우기준)/2` 입력을 사용하는 LSTM 후보를 새로 학습했다.
- 기존 다층 LSTM 대신 LSTM 16유닛 → Dense 8유닛 → Dropout → 이진 출력으로 규모를 줄였다.
- 약 0.97초를 30개로 보간하는 같은 시간 입력을 학습과 추론에 사용했다.
- 라벨 불균형을 class weight로 보정했다. 입력 스케일러는 학습 프레임에만 적합했다.
- 검증 손실 기준으로 조기 종료하고 최적 가중치를 복원했다. 23 epoch를 실행했다.
- 검증 재현율 90% 이상인 임계값 중 정상 오판정 비율이 가장 낮은 값을 선택했다.
- 선택된 모델 임계값은 0.02다. 교정된 졸음 확률을 의미하는 값은 아니다.

|---|---|---:|---:|

알 수 없는 라벨, 미검출, 보정 전 관측을 제외하고, 제외 구간에서 입력을 끊었다.
입력 완료 시점의 정답 라벨을 사용했다. 각 시퀀스는 최고 10 Hz 간격으로
추출했으며 서로 겹치므로 시퀀스 수는 독립 시험 횟수가 아니다.
첫 기록 session_6은 라벨 혼동 가능성이 있어 학습에서 제외했다.

## 원시 모델 비교

기존 모델도 같은 테스트 시점과 시간 윈도우로 재추론했다. 기존 모델은
원시 EAR와 기존 스케일러, 새 모델은 개인별 EAR와 새 스케일러를 사용했다.
따라서 모델·입력 보정·임계값을 포함한 후보 묶음의 비교이며, 구조 변경만의 효과를 분리한 실험은 아니다.

| 지표 | 기존 모델, 임계값 0.5 | 새 후보, 검증에서 선택한 임계값 0.02 |
|---|---:|---:|
| 정확도 | 47.84% | 79.61% |
| 정밀도 | 14.67% | 30.35% |
| 재현율 | 98.08% | 95.51% |
| F1 | 25.52% | 46.06% |
| 정상 프레임 오판정 비율 | 57.20% | 21.98% |
| TP / FP / TN / FN | 153 / 890 / 666 / 3 | 149 / 342 / 1,214 / 7 |

후보는 오판정이 줄었지만 정밀도는 아직 낮으며 누락도 일부 증가했다.

## 전체 판정 비교

두 모델을 전체 session_9 기록에서 다시 추론하고, 같은 최신 눈 상태·시간 판정 규칙에 입력했다.
두 모델에 각자 대응하는 모델 임계값을 사용했다.

| 지표 | 기존 모델 + 최신 규칙 | 후보 모델 + 최신 규칙 |
|---|---:|---:|
| 최종 판정 정확도 | 87.10% | 87.17% |
| 정상 구간 새 경고 | 17회 | 17회 |
| 평균 경고 해제 시간 | 1.364초 | 1.364초 |
| 평가 가능한 완료 시험 성공 / 누락 | 1 / 0 | 1 / 0 |
| 시작 전 경고 중인 시험 | 3회 | 3회 |

원시 모델 성능 개선이 전체 오경보 감소로 이어지지는 않았다.
눈 상태 규칙이 최종 판정에 강하게 작용하고 있으며, 개인 기준·얼굴 자세·눈 랜드마크의 변화와
실제 행동 라벨의 일치를 추가로 확인해야 한다. 모델 교체만으로 전체 문제가 해결됐다고 볼 수 없다.

## 산출물 및 재현

후보 폴더: `backend/ai_models/candidates/20261013_195253_465521/`

- `best_drowsy_model.keras`: 실제 학습한 새 모델
- `ear_scaler.pkl`: 새 모델에 대응하는 입력 스케일러
- `metadata.json`: 입력 방식, 임계값, 시간 범위, 데이터 분할·파일 SHA-256
- `evaluation.json`: 원시 모델 비교, 검증 임계값 선택, 학습 이력
- `test_predictions.csv`: 동일 테스트 입력 시점의 정답과 기존·후보 점수
- `pipeline_evaluation.json`: 모델 재추론 후 전체 판정 비교

```powershell
python model_training/train_model.py --train backend/diagnostics/session_7_20261012_235458.csv --validation backend/diagnostics/session_8_20261013_000911.csv --test backend/diagnostics/session_9_20261013_002920.csv --epochs 30
python model_training/evaluate_candidate.py --candidate backend/ai_models/candidates/20261013_195253_465521 --recording backend/diagnostics/session_9_20261013_002920.csv
```

기존 모델은 덮어쓰지 않았으며 후보 실행은 `DROWSINESS_MODEL_DIR`로 명시적으로 선택한다.
서버와 클라이언트는 선택된 입력 방식과 임계값을 사용하고 실제 모델 경로·코드 버전을 표시한다.

## 한계와 다음 검증

정답은 사용자의 키 입력이며 실제 졸음에 대한 의학적 정답이 아니다.
한 사람의 소수 촬영 세션이므로 다른 사람·조명·안경에 대한 일반화는 입증하지 못했다.
테스트 파일은 가중치 학습과 임계값 선택에서는 제외했지만, 이전 판정 규칙 개발 중에는
이미 분석했던 기록이다. 전체 시스템의 완전히 독립적인 테스트라고 할 수 없다.
촬영을 새로 하지 않고 기존 랜드마크를 재사용했으므로 얼굴·눈 측정 성능도 다시 검증한 것은 아니다.

다음 새 촬영에서는 먼저 `/health`와 클라이언트 출력으로 실제 후보와 최신 코드 적용을 확인한다.
그 뒤 원시 모델 통계와 최종 경고 사건을 별도로 평가하고, 새 오경보 순간의 얼굴 자세와
눈 상태를 확인해야 한다. 추가 촬영 데이터를 학습에 넣을 경우 별도 테스트 기록을 남겨두어야 한다.

## 후속 새 촬영 검증

session_10에서 후보와 v3 적용을 확인했고, session_11에서 후보와 v4 적용을 확인했다.
두 기록은 위 모델의 가중치 학습·분류 임계값 선택에 사용하지 않았다.
session_10은 이후 v4 경고 조건을 정하는 데 사용했으므로 v4의 독립 확인으로 간주하지 않는다.

session_11 실제 v4 요약은 최종 정확도 96.1%, 정밀도 76.8%, 재현율 80.8%,
새 정상 경고 1회, 완료 눈 감김 시험 4/4 감지, 평균 첫 경고 지연 1.57초,
평균 해제 시간 1.34초였다. 현재 개인 환경에서 후보+v4 설정을 유지하는 것을 권장한다.
추가 동일 시험을 반복하기보다는 새로운 사용자·환경으로 확장할 때 검증한다.

규칙의 같은 기록 비교와 남은 한계는 `entry_rule_comparison.md`, 전체 완료 범위는
`improvement_progress.md`에 기록했다. 검증 당시에는 후보를 환경변수로 선택했다.
후속 앱 적용에서 동일한 모델·스케일러를 `released/personal-ear-v1`로 복사해
기본 실행에 연결했다. 원본과 실험 후보는 보존하며 명시적 모델 설정은 기본값보다 우선한다.
