# 개선 진행 상태

## 2026-10-14 경보 중지 후 회복 정책 — v6

현재 실행 버전은 `event-risk-v6`다. 2·3단계 모두 앱 경보 중지 확인 후 정상 눈 상태 10초로 바로 0단계에 복귀한다.
중지 확인 전 정상 시간은 포함하지 않으며 회복 시 사건 이력을 비운다. 개인 보정과 DB 위험 로그는 유지한다.
새 사건·긴급 조건 발생은 기존 중지 확인을 무효로 한다. 미검출·눈 처짐은 정상 회복 타이머를 끊는다.
`POST /detection/alarm/acknowledge`를 앱 중지 버튼에서 호출해야 한다. 테스트 클라이언트와 독립 도구의 `m`으로 시험할 수 있다.
자동 테스트 64개가 통과했다. 실제 앱 버튼 연결은 Flutter 소스가 없어 앱 저장소에서 수행해야 한다.

## 2026-10-14 이전 단계 정책 — v5

당시 실행 버전은 `event-risk-v5`였다. 모델·개인 보정은 그대로 유지하고 단계 정책을 변경했다. 아래 회복 조건은 v6에서 대체했다.
사건 진입은 1.25초, 최근 30초 사건 2회는 2단계, 2단계 이후 새 사건은 3단계다.
양쪽 눈 감김 3초는 긴급 조건으로 즉시 3단계다. 눈 재개방 0.5초가 확인돼야 새 사건을 셀 수 있다.
1단계는 정상 관측 10초 후 해제, 2단계는 정상 관측 30초·최근 사건 없음·EAR 눈 감김 비율 10% 이하를 만족하면 1단계로 회복하며 이후 10초를 더 확인한다.
3단계는 새 감지 세션까지 위험 기록을 유지한다. 얼굴 미검출은 회복으로 처리하지 않는다.
경고음은 앱의 사용자 중지 버튼에서 제어하며 서버 단계 회복과 분리한다.

v4 촬영 결과는 이전 정책의 검증 기록이다. v5 전환·회복·미검출·사건 중복 방지 테스트를 포함해 자동 테스트 55개가 통과했다. 실제 촬영·앱 버튼 연동은 추가 확인 대상이다.
현재 정책의 수치는 개발용 시작값이며 도로 안전성 검증을 의미하지 않는다.

## 기존 모델 개선 기록

기존에 합의한 5단계 기준으로 정리했다.

| 단계 | 상태 | 확인한 근거 |
|---|---|---|
| 1. 입력·감지·평가 오류 수정 | 완료, v4 조건 추가 반영 | 시간 입력 통일, 개인 보정, 경고 해제, 통계 분리, 서버 버전 확인 |
| 2. 개선 코드 실제 촬영 테스트 | 완료 | session_10에서 v3, session_11에서 후보 경로·v4·최소 시간 1.25초 확인 |
| 3. 기존 모델 평가와 학습 데이터 보강 | 현재 사용자 기록 범위에서 완료 | 라벨 혼동 가능 기록 제외, session_7/8/9 분리, session_10 새 촬영 비교 |
| 4. 새 후보 모델 재학습 | 완료 | 후보 20261013_195253_465521, 23 epoch, 모델·스케일러·메타데이터 저장 |
| 5. 동일 데이터 비교 후 적용 결정 | 현재 개인 환경의 시험 설정 결정 완료 | session_11에서 v3/v4 비교와 실제 v4 시험 확인; 후보+v4 사용 유지 권장 |

현재 지점은 **현재 사용자·카메라 환경의 기본 개선과 확인 시험 완료**다.
후보는 환경변수로 선택해 실행할 수 있으며 기존 모델을 덮어쓰지 않았다.
후속 앱 적용 작업에서 검증한 후보를 `released/personal-ear-v1`로 복사하고 기본 선택으로 연결했다.
이제 모델 환경변수 없이 일반 서버 실행에서 새 모델을 사용하며, 명시한 모델 설정은 우선한다.
v4 작업은 후보 가중치 재학습이 아니라 경고 진입 조건 조정이었다.

## 성능 확인 범위

평균 경고 지연 0.757→1.490초였다. 초기 대기 때문에 프레임 누락은 증가했다.
자동 테스트 28개와 구문 검사, 서버·클라이언트 버전 일치 및 후보 로드 검사를 통과했다.

## v4 새 촬영 확인 완료

session_11_20261013_213448.csv에서 실제 후보 경로와 코드 v4를 확인했다.
정상 라벨 시간은 약 336.4초이며, 새 경고는 1회였다. 긴 눈 감김 시험은
4회 모두 감지했고 평균 지연은 1.57초, 눈 뜬 후 평균 해제 시간은 1.34초였다.
최종 프레임 정확도 96.1%, 정밀도 76.8%, 재현율 80.8%였다.

같은 session_11의 고정 모델 점수에 v3/v4 규칙을 적용한 비교에서도
새 경고 8→1회, 완료 시험 4/4 성공을 확인했다. 평균 첫 경고 지연은
0.798→1.544초로 늘었다. 실제 키 입력부터 측정한 클라이언트 요약과
기록의 첫 라벨 프레임부터 측정한 재생 수치는 조금 다르다.

session_11은 v4 조건 선택에 사용한 session_10 이후 촬영한 확인 기록이다.
이번 결과로 조건을 다시 조정하지 않았다. 새 기록의 성공 사례는 4회뿐이며,
개인 환경의 기본 확인을 여러 환경의 신뢰성 검증과 혼동하면 안 된다.

## 남은 한계와 확장

- 정상 라벨 경고 1회가 남았다. 그 순간 양쪽 눈 EAR는 기준의 약 77%·74%였고,
  점수 0.0286이 임계값 0.02를 넘어 1.29초 누적되어 모델 경로로 경고했다.
  영상이 없으므로 고개·시선·눈 상태 중 실제 원인을 확정할 수 없다.
- 정상 경고 프레임 132개 중 88개는 눈을 뜬 후의 경고 해제 대기,
  나머지 44개는 위 새 경고에 해당했다.
- 경고 전 대기로 초기 눈 감김 프레임은 누락에 포함된다. 사건 4회 감지와
  프레임 재현율 80.8%는 서로 다른 평가다.
- 경고 지연이 실제 용도에 적절한지는 사용자 체감과 요구사항으로 판단해야 한다.
- 여러 사용자·환경에 대한 적용은 추가 검증 범위다. 지금 같은 시험을 더 반복할 필요는 없다.

여러 사람·안경·조명·카메라 조건의 일반화 및 실제 졸음 검증은 별도 확장 단계다.
현재 개인 환경의 기본 개선 완료와 구분한다.

관련 보고서: `model_comparison.md`, `decision_comparison.md`, `entry_rule_comparison.md`.

## 실제 앱 경로 적용

- 통합 후 자동 테스트 40개와 기본 모델 로드·추론 검증이 통과했다.
- 서버 직결 웹캠의 실제 열기·5프레임 처리·해제를 확인했다. 해당 확인에는 얼굴 검출이 없었다.
- 서버 직결 웹캠 방식의 기존 감지 API에 기본 배포 모델과 v4를 연결했다.
- 백엔드와 독립 실행 `realtime_detect.py`가 카메라 처리·개인 보정·추론·판정을 공유한다.
- 경고 활성/상승 신호와 관측 유효 여부를 앱에 전달하며 기존 응답 필드를 유지한다.
- 카메라 시작·읽기·추론 실패를 앱에 전달하고 종료 시 카메라·랜드마커를 해제한다.
- 서버 종료 시 활성 감지 세션을 정리한다.
- 배포 묶음의 체크섬과 기본 로드를 검증한다. 원본 모델과 실험 후보는 보존한다.

Flutter 소스는 이 저장소에 없어 모바일 화면·소리·진동은 직접 수정하지 않았다.
연결 계약과 일반 실행 방법은 `backend/APPLICATION_INTEGRATION.md`에 기록했다.
